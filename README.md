# はんのうノート

食べたあとに出た皮膚の反応を、写真と時刻つきで記録するPWA。
2台の端末でファイルを渡し合って同期できる。

## ファイル

| ファイル | 役割 |
|---|---|
| `index.html` | 本体（単一ファイル、外部依存なし） |
| `manifest.json` | ホーム画面追加の設定 |
| `sw.js` | オフライン用 Service Worker（キャッシュ名 kuchi-log-&lt;版&gt;） |
| `icon-192.png` / `icon-512.png` | 通常アイコン |
| `icon-maskable-512.png` | Androidの円／角丸切り抜き用 |

6ファイルすべてを**同じフォルダ**に置く。ファイル名は変えない。

## 配備

### Termux + localhost（外部に出さない）

```
pkg install python
cd <ファイルを置いたフォルダ>
python -m http.server 8080
```

Chromeで `http://localhost:8080/` を開き、メニューから「ホーム画面に追加」。
追加後はサーバを止めてよい（Service Workerがキャッシュ済み）。

### GitHub Pages（一時公開）

リポジトリをPublicにして6ファイルを配置 → 公開URLを開いてホーム画面に追加 →
Privateに戻す。更新するときだけ一時的にPublicにする。

`file://` で直接開いても動くが、ホーム画面追加とオフライン動作は
http配信でないと有効にならない。

## 使い方

1. 症状が出たら、赤いタイルの「📷 カメラでとる」を押す。カメラがすぐ起動する
2. 撮った写真はタイルの棚に並ぶ。「＋」でもう1枚、サムネの「×」で保存前に取り消せる
3. 製品・原材料表示は落ち着いてから足す。写真1枚で保存できる。
   写真が1枚もないときは、保存ボタンの上に押せない理由が出る
4. 「食べたのは」と「強さ」は1つだけ、「出た場所」はあてはまるものぜんぶ選べる。
   どちらなのかは見出しの横に書いてある
5. 食材はチップから選ぶ。一覧にないものだけ手入力（表記ゆれを防ぐため）
6. 製品名や食材は「くわしく書く」から。保存したあとは記録カードの「記録を直す」で足せる。
   「原材料表示から取り込む」に表示の文字を貼ると、アレルゲンを候補として出す
   （下の「原材料表示の読み取り」参照）
7. タイル下の「🖼 アルバムから選ぶ」でアルバムから追加。撮影日時（EXIF）が記録日時になる
8. 保存した記録に足すときは「📷 写真を足す」。症状・製品・原材料表示と
   カメラ／アルバムを1画面で選ぶ
9. 写真はタップで拡大。左右スワイプで送れる。拡大画面から1枚だけ消せる
10. 記録を削除するときは確認が出る。消したあとも「取り消す」が8秒出て、
    写真は7日間残るので戻せる

入力の途中でアプリを閉じても、撮った写真ごと下書きが残る。
次に開くと「書きかけの記録を戻しました」と出る。

## 原材料表示の読み取り

写真そのものを解析はしない（端末外に出さないため）。文字にするのは端末側でやる。

1. 撮った原材料表示の写真を、端末の文字認識で読む
   - Android: Googleレンズ、または写真を長押しして「テキストを選択」
   - iPhone: 写真を長押し／□アイコンから「テキストを認識」
2. 出てきた文字をコピー
3. 「くわしく書く」→「原材料表示から取り込む」に貼り付け
   （保存したあとの記録なら「記録を直す」から）

貼ると、アプリが持っている食材名と照らして **候補チップ** を出す。

- チップを押すと「気になる食材」に入る。「ぜんぶ入れる」で一括
- 押しても入るだけで、勝手には確定しない
- 「小麦は使用していません」のような打ち消しは拾わない
- 「同じ設備で製造」などのコンタミ表記は候補に入れず、注意文だけ出す
- **表示に出ていない＝入っていない、ではない。** 写真の表示を必ず自分で確認する

照らし合わせに使う語は `index.html` の `LABEL_MAP`。増やしたいときはここに足す。

## 共有

「共有と書き出し」を開き、端末名（パパ／ママ）を入れておく。
中は「送る」「受け取る」「受診用・バックアップ」に分かれている。

- **同期ファイルを作る** — 前回から変わったぶんだけZIPにする
- 相手が **同期ファイルを読み込む** → 取り込む件数を確認して確定
- 取り込むと「◯◯へ返信ファイルを作る」が出るので、押して往復を閉じる

受診用の「ぜんぶ書き出す」ZIPは、同期ファイルとしても読める。
新しい端末にこれを読み込ませれば全記録を復元できる。

ZIPは必ず**ファイルとして**送る。写真として送ると再圧縮されて壊れる。
中身は暗号化していないので送り先に注意。

## 集計の読み方

食材ごとの回数は「反応が出たとき」だけの数なので、そのままでは分母がない。
食べても平気だと分かった食材は「大丈夫だった食材」に入れると候補から外れる。
残ったものが絞り込みの候補になる。

一覧の上には直近30日の件数と、前の30日との増減が出る。

## 仕組みのメモ

- データはIndexedDB（DB名 `kuchi-log`）に保存。外部送信は一切ない
- 同期の差分判定は時刻ではなく版番号（Lamportクロック）。時計がずれても壊れない
- 競合は版番号→端末IDで決着。両端末が必ず同じ結果に収束する
- 削除は墓標として残るので、古いZIPを読み直しても復活しない
- 写真は内容ハッシュで重複排除。同じ写真は二重に入らない
- 消した写真もハッシュで墓標に残るので、同期で復活しない
- 削除の取り消しは版番号で伝わる。相手の端末でも記録が戻る

## バージョン

いま動いているのがどの版か、端末上で確かめられる。

- タイトル右の版バッジ（例 `v1.1.0`）を押すと、版・ビルド日・オフライン用データの状態が出る
- 新しい版を配ったあとにアプリを開くと、バッジに `●` が付く（＝ダウンロード済み・未適用）
- バッジ →「更新して開き直す」で切り替わる。記録は消えない
- 端末2台で番号が違うときは、古いほうがまだ前の版のまま

### 版を上げる手順（配布側）

1. `index.html` の `APP_VERSION` と `APP_BUILD` を書き換える
2. `sw.js` の `VERSION` を **同じ番号** にする（ここがズレるとキャッシュが入れ替わらない）
3. Git でコミットしてタグを打つ

```
git add -A
git commit -m "v1.1.0: 変更点の要約"
git tag v1.1.0
```

番号は `メジャー.マイナー.パッチ`。使い勝手が変わる直しはマイナー、
表示崩れやことばの直しだけならパッチを上げる。

- **1.2.0** — UI・UXの刷新。押す場所と選べる範囲を画面に出した

    サムネの棚から保存前に1枚だけ取り消せる

  - 開閉できる欄をカード状の帯にし、開閉の山形と中身のバッジを付けた
  - 記録カードの操作を「写真を足す／記録を直す／⋯」に整理し、削除に確認を追加
  - シートは背景タップとEscでも閉じられる
  - 経過のお知らせの「あとで」が二度と出なくなる不具合を修正（4時間の先送りに）
  - 「書き足す」の二重の意味を「くわしく書く」と「記録を直す」に分けた
- **1.1.0** — 「原材料表示から取り込む」欄を追加。貼り付けた文からアレルゲンを候補提示
- **1.0.0** — 版バッジと更新確認を追加

## 注意

- ブラウザのサイトデータを消すと記録も消える。定期的に「ぜんぶ書き出す」こと
- HEIC形式の写真は表示・日時取得ができない場合がある
- 全身にじんましんが広がる、吐く、息が苦しそう ── 記録より先に受診
